## 运行当前测试

在 `server` 目录安装开发依赖后运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

`requirements.txt` 只保留运行时依赖；测试工具固定在 `requirements-dev.txt`，避免生产镜像不必要地携带测试器。所有测试同时兼容标准库运行方式：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

当前测试通过 `tests/_support.py` 在导入应用模块前强制设置 `APP_ENV=testing`、内存 SQLite，并为各用例创建临时/隔离数据库；不应连接或写入开发数据库。

## 测试安全要求

1. 新测试必须先导入 `tests._support`，再导入会初始化数据库连接的 `app.*` 模块；不得依赖开发者本机 `.env`。
2. 单元和服务测试只使用内存/临时数据库、假的 OpenID/手机号/地址和模拟支付、短信、地图、对象存储；禁止使用真实用户数据或真实扣款渠道。
3. 需要 MySQL 语义时使用一次性、名称明确的测试实例/数据库，并加环境保护：非 `testing`、库名不符合测试约定或目标不可确认时立即失败。
4. 清理只针对用例自己创建且已验证的临时数据库/表；不执行面向开发库、工作区根目录或不确定目标的广泛删除。
5. 测试输出、失败快照和 CI 附件不得包含完整 DSN、密钥、验证码、OpenID、身份证、银行卡、电话、精确地址、聊天正文、证据 URL 或原始坐标。
6. 迁移测试先在临时库运行；任何 `stamp`、downgrade 或数据修复测试不得指向共享环境。
7. 资金测试必须使用精确金额类型并验证“失败无副作用”；不能只断言 HTTP 200 或状态文本。

## v6.3 必要覆盖矩阵

下列项目是目标上线门槛；未列入当前测试文件的均视为缺口。

### 1. 同账号双角色与权限

- 同一可信微信身份只生成一个稳定账号，可同时关联用户和师傅档案。
- 仅用户档案、仅师傅档案、双档案、冲突身份标识和停用账号均有确定结果。
- 角色切换不是登出：切换后产生目标角色上下文，旧角色任务/草稿/资金操作不丢失，返回栈不跨角色。
- 用户令牌不能调用师傅动作，师傅令牌不能读取其他用户/师傅的对象；同一账号拥有双角色也不能绕过对象归属。
- 服务端正确返回角色可用/需开通/审核中/受限状态及可修复阻断原因。
- 师傅资格过期默认阻止新报价，但已有订单、钱包查询、客服和申诉仍可访问。

### 2. 五轴状态、版本与 `allowed_actions`

- `service_state`、`payment_state`、`aftersale_state`、`price_adjust_state`、`acceptance_state` 独立变化且不互相覆盖。
- `pricing_mode`、`empty_run_fee_state` 和 `pending_dispatch` 在列表/详情/动作合同中稳定返回。
- 售后、退款、待某方操作和普通履约的主状态优先级与交互文档一致。
- 每个角色、每组状态返回正确且唯一的 `primary_action`、`allowed_actions` 和带原因的 `blocked_actions`。
- 前端读到动作后对象被并发修改，提交必须以版本冲突失败并返回最新状态；旧事件不能让状态倒退。
- 旧 `Order.status` 到五轴的迁移映射覆盖 `paid`、`reviewed`、`cancelled` 和支付/退款事实冲突。

### 3. 报价、资格与价格

- 报价覆盖 `draft / submitted / selected / not_selected / expired / withdrawn` 的合法与非法迁移、版本和截止时间。
- 同一订单同一师傅有效报价唯一；并发选报价只有一个 `selected`，选中、指派、`pending → accepted` 和价格快照原子一致。
- 一口价/自己定价并发接单只有一个成功；失败方收到“已被其他师傅接单”，订单状态和版本正确。
- 重复幂等键返回第一次报价/选定/接单结果；同键不同请求被拒绝。
- 报价时服务端校验账号、实名、类目、培训、区域、保证金/保障、额度和订单有效性，并返回具体缺项。
- 定位权限不阻止浏览或报价，只在出发时成为前置。
- 中标前订单摘要遮罩精确地址和电话。
- 完工金额只能等于“中标报价 + 已接受差价 - 有效优惠”等服务端结果；自由改价被拒绝。
- 差价待确认阻止完工；超时不自动同意/扣款/成功；已接受差价只计一次；元/分和舍入边界正确。

### 4. 位置追踪会话

- 出发与订单级追踪会话原子创建；页面退出、导航、电话、前后台切换不终止会话。
- 会话只能绑定中标师傅和对应订单；其他主体、其他订单或已停止会话上报被拒绝。
- 重复 `sequence` 幂等，乱序点不覆盖最新点；并发上报保持单调版本。
- 超过 60 秒（或服务端策略值）进入 `stale`，不再给不可靠 ETA；恢复上报后状态正确恢复。
- 到达、取消和平台终止记录不同 `stop_reason`；结束后实时接口不继续泄露位置。
- 轨迹查询覆盖订单归属、管理员专项权限、留存边界和日志脱敏。

### 5. 支付、结算与资金桶

- 支付请求、渠道回调、退款、提现分别覆盖相同键重放、不同请求复用键、并发和超时查询。
- 渠道交易号唯一；金额、币种、商户和业务单校验失败时余额、分录、订单状态均不变化。
- `pending_settlement / available / frozen / withdrawing / withdrawn / reversed` 转移守恒，任何时点均可由不可变分录重建。
- 同一订单只结算一次；部分退款累计不超原支付；售后冻结与解冻金额准确。
- 提现原子冻结可用余额；处理中不重复申请；失败释放原金额；结果未知查询原申请。
- 结算快照可解释中标报价、差价、优惠承担、费率来源、平台费、净收入、退款/扣款和预计时间。
- 保证金与收入钱包分离，保证金变化不污染收入桶。
- 师傅收入钱包拒绝充值和师傅间转账；用户余额充值与保证金缴纳不能误入师傅收入桶。

### 6. 幂等、事件与消息深链

- 所有关键写操作均覆盖相同键相同请求、相同键不同请求、并发相同键、处理中重试和完成后重放。
- 状态写入与领域事件/发件箱同事务；事务回滚不留下孤立消息，发送失败可重试但不重复业务效果。
- 重复、乱序和延迟事件按 `event_version` 去重，不能覆盖更新状态。
- 消息载荷强制包含 `role`、`object_type`、`object_id`、`event_version`、`fallback_route`。
- 角色不匹配时可切换后继续；对象状态已变时进入最新详情；对象删除/无权时落到稳定兜底。
- 只有目标成功加载后标记已读，跳转失败和待切换角色时保持未读。

### 7. 隐私与审计

- 可接单列表、报价、消息、错误响应和导出不会在授权前泄露精确地址、电话、证件、银行卡或坐标。
- 自动扫描应用日志、审计日志和测试输出，确保敏感原文被禁止或掩码；尤其覆盖短信、支付、地图和异常堆栈。
- 管理员查看/导出敏感信息、人工改订单、退款/冻结/提现审批、资格变化和位置强制终止均生成结构化审计。
- 审计记录包含操作者、角色、对象、结果、原因、请求 ID、策略版本和脱敏摘要，但不保存聊天/证据正文或原始轨迹。
- 越权读取返回一致的 403/404 策略，不通过差异响应枚举他人对象。

### 8. 迁移与兼容

- 从空库、上一 revision 和代表性旧库均可升级到 `head`；ORM 无漂移。
- 双角色回填不错误合并重复 OpenID/UnionID，冲突进入异常清单。
- 单状态、`is_selected`、`approved` 差价、旧消息和单余额按后端契约映射并有逐项报告。
- 升级中断后可恢复，回填可重复执行；不会重复创建账号、报价、事件或资金分录。
- 新旧响应兼容期内旧 `status` 与五轴投影一致，客户端切换到 `allowed_actions` 后再移除旧依赖。
- 一次性 MySQL 8 真实升级、关键索引/约束、锁表时间和迁移后资金对账通过。

## 推荐测试层级

| 层级 | 重点 |
|---|---|
| 纯单元测试 | 状态投影、主动作、资格规则、价格与资金计算、脱敏函数 |
| 服务/事务测试 | CAS、幂等、报价选定、差价、结算、事件发件箱的原子性与并发 |
| API 合约测试 | 鉴权、对象归属、角色上下文、错误码、版本、响应遮罩和 OpenAPI |
| 迁移测试 | SQLite 快速回归 + 一次性 MySQL 8 真实升级、回填和约束 |
| 集成/沙箱测试 | 微信支付/退款查询、短信、地图、对象存储；只用沙箱和假数据 |
| 安全与隐私测试 | IDOR、角色越权、敏感日志扫描、审计完整性、深链失效与重放 |

## 完成定义

一个目标能力只有同时满足以下条件才可在文档或发布说明中标为“已实现”：

- 代码与数据库迁移已经合入；
- OpenAPI 明确请求、响应、鉴权、版本、幂等和错误语义；
- 正常、异常、并发、重试、越权和隐私用例齐全并通过；
- 一次性 MySQL 8 迁移与关键外部服务沙箱验证通过；
- 客户端只按服务端状态与 `allowed_actions` 呈现操作，失效深链和处理中任务有恢复落点；
- 资金与身份迁移完成对账，日志/审计不含敏感原文。
