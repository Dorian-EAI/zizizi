# 运行时与对象存储上线说明

本说明覆盖服务端对象存储删除、同步第三方 SDK 隔离、多进程与定时任务边界。它不会替代云控制台、真实 Redis/MySQL 或短信/地图供应商的上线演练。

## 对象存储安全边界

- `development/testing` 可使用 `/uploads/...` 本地文件；`staging/production` 配置校验禁止 `local`。
- 阿里云 OSS 与腾讯云 COS 删除只接受当前配置 bucket 的 origin 或显式 CDN 主机，必须为 HTTPS，拒绝用户信息、非 443 端口、查询参数、片段、相似后缀域名和编码路径。
- 对象 key 必须匹配服务端生成的 `分类/年/月/日/32位随机名.扩展名`；`certificate` 还必须匹配 `certificate/{worker_id}/...`。接口不能删除 bucket 中任意 key。
- 认证材料上传强制私有 ACL、绕过公共 CDN，后台读取只生成十分钟短签名 URL。
- `DELETE /api/upload/file` 仅 `super_admin` 可用。执行外部删除前先落一条 `attempted` 审计，结束后更新为 `deleted`、`not_found` 或 `failed`；`target_id` 保存受管对象 key 以便追溯，详情不保存原 URL、签名参数或访问凭证。
- 上线前必须在云控制台配置并演练对象版本、未完成分片终止、归档/清理策略，再把 `OBJECT_STORAGE_LIFECYCLE_CONFIRMED=true`。未确认时 staging/production 拒绝启动。仍被认证记录引用的证件不得仅依赖 bucket 自动过期；应按隐私与合规保留期由超级管理员执行受审计删除。

## 同步 SDK 与事件循环

- 地图和短信端点改为同步 FastAPI 路由，由框架在线程池运行供应商的同步 SDK。
- 上传在异步分块读取后，把 OSS/COS 上传与删除放入线程池。
- 师傅认证把对象存在性检查、短信核验和对应事务作为同一线程池调用；后台证件短签名路由也由同步线程池执行。
- 异步消息通知中的真实短信调用已移出事件循环。微信订阅消息仍使用原有异步 HTTP 链路。

## 多进程、调度器与批处理

- `WEB_CONCURRENCY` 控制 `run.py` 的 Uvicorn worker 数，允许 1–32；开发热重载必须为 1。容器平台也可保持每 Pod 一个进程并横向扩容。
- 多 worker/多副本开启 `SCHEDULER_ENABLED` 时，任务仍通过 Redis 所有者令牌锁去重；部署环境 Redis 不可用时任务跳过，不会无锁执行。上线应实测主 Redis 与限流 Redis 两套连接。
- 订单历史、可抢单、竞价、优惠券、培训记录、回访、工单回复和配置列表保留原数组响应，但增加硬上限。
- 自动取消、优惠券过期、评价审核、工单关闭、退款审核和提醒任务按有界批次处理；积压由后续轮次继续消化，避免一次性 `.all()` 拉取全表。

## 资金写请求幂等与钱包边界

- `POST /api/wallet/recharge`、`POST /api/wxpay/recharge/jsapi`、`POST /api/wallet/pay`、`POST /api/wxpay/order/jsapi`、`POST /api/wallet/refund` 接受标准 `Idempotency-Key` 请求头；staging/production 缺失时返回 428，不能创建支付单或退款单。
- 客户端键为 8–128 位不透明字符串。同一账号下，一个键永久绑定首次操作和规范化请求摘要：同键同请求重放首次完整结果，同键改金额、优惠券、订单或操作返回 409。
- 幂等占位在业务调用前独立持久化。服务中断留下 `processing` 时返回 409 并要求按业务单号核对，绝不因自动重试再次移动资金。已知业务失败同样持久化并重放；需要重新尝试时必须由客户端生成新键。
- development/testing 为尚未升级的本地客户端生成稳定的 `legacy-*` 键以兼容调试；部署环境没有此降级。小程序应在用户点击一次资金动作时生成键，并在网络重试、页面恢复和支付结果轮询期间复用，只有明确开始一笔新动作才更换。
- 普通用户可以充值用户余额；师傅收入钱包不开放充值，师傅令牌访问两条充值入口均被拒绝。保证金继续使用独立业务入口。生产提现/转账仍失败关闭，不把占位接口描述为到账成功。

## 上线核验

1. 以生产环境变量运行 `python scripts/check_production_readiness.py`，配置门禁必须全部通过。
2. 分别在 OSS/COS 测试 bucket 演练上传、私有证件短签名、精确 key 删除、错误域名拒绝和删除审计。
3. 用至少两个 web worker 同时触发一个测试定时任务，确认只有一个 Redis 锁持有者执行。
4. 模拟 Redis、短信、地图和对象存储超时，确认 API 有界失败且事件循环仍可响应健康检查。
5. 对超过单批上限的测试数据运行两轮任务，确认无漏处理且内存稳定。
