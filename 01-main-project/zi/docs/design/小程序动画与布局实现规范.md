# 小程序动画与布局实现规范

> **版本与效力**：v6.3。发生冲突时，按 `PRD v6.3` → `docs/design/功能与交互文档.md v6.3` → `docs/design/样式规范详尽文档.md v6.3` → 后端 v2 规格 / 经评审 API 与数据合同（仅技术字段）→ 本文 → `pages/` HTML / `zjrnew.design` 的顺序执行。
>
> **证据边界**：本文中的 HTML、CSS、阈值与画布只用于说明设计和实现方式，不是功能已经上线、规则已经开放或可用性已经通过验收的证据。业务事实始终以 PRD 与服务端返回为准。
>
> **术语与业务基线**：统一使用“用户端 / 师傅端”。两端根页面各固定 4 个 Tab；当前开放一口价、报价、自己定价三种模式；悬赏、平台强制派单、自动接单与指定师傅直接成交隐藏；用户不能确认到达，只有师傅可执行“到达”与“开始服务”；AI 助手、订单聊天、人工客服是三个独立入口；支付方式仅展示接口返回的微信支付、余额及组合支付，线下支付仅在配置开启时出现，不展示支付宝或银行卡；追加费用仅更新最终应付金额，不立即扣款；空跑费/加速费按服务端规则展示；加急费及费率只用服务端返回值，不得写死比例；页面隐藏或退到后台不得结束行程定位会话。
>
> **状态字段**：页面分别消费履约 `service_state`、支付 `payment_state`、售后 `aftersale_state`、追加费用 `price_adjust_state`、验收 `acceptance_state`、空跑费 `empty_run_fee_state` 和定价模式 `pricing_mode`；布局、按钮和过渡动画均服从服务端 `allowed_actions`，不得用单一页面状态合并推断。

## 一、字体轻量化部署（防画布闪退）

### 1.1 已部署方案

`zjrnew/assets/fonts.css` 已采用子集化 WOFF2，不加载完整中文字体：

```css
@font-face {
  font-family: 'Cormorant Garamond';
  font-style: normal;
  font-weight: 700;
  font-display: swap;
  src: url('./CormorantGaramond-Bold.woff2') format('woff2');
}

@font-face {
  font-family: 'Noto Serif SC';
  font-style: normal;
  font-weight: 400;
  font-display: swap;
  src: url('./NotoSerifSC-Regular.subset.woff2') format('woff2');
}

@font-face {
  font-family: 'Noto Serif SC';
  font-style: normal;
  font-weight: 700;
  font-display: swap;
  src: url('./NotoSerifSC-Bold.subset.woff2') format('woff2');
}
```

### 1.2 为什么能防闪退

| 优化点 | 说明 |
|--------|------|
| 子集化 WOFF2 | 仅保留页面实际用字，体积最小 |
| `font-display: swap` | 字体未加载完时先显示系统回退字体，避免 FOIT 空白/闪退 |
| 仅 400/700 字重 | 不加载完整字重家族，减少内存 |
| 全局衬线回退 | `STSong`、`Georgia`、`serif` 兜底，禁止无衬线混用 |

### 1.3 微信小程序迁移

小程序 WebView / 原生页不支持本地 `@font-face`，需：

1. 将 `assets/` 下字体文件上传到 HTTPS CDN（加入业务域名白名单）。
2. 在 `app.js` 或页面 `onLoad` 中调用 `wx.loadFontFace`：

```js
wx.loadFontFace({ family: 'Noto Serif SC', source: 'url("https://your-cdn.com/fonts/NotoSerifSC-Regular.subset.woff2")' });
wx.loadFontFace({ family: 'Noto Serif SC', source: 'url("https://your-cdn.com/fonts/NotoSerifSC-Bold.subset.woff2")' });
wx.loadFontFace({ family: 'Cormorant Garamond', source: 'url("https://your-cdn.com/fonts/CormorantGaramond-Bold.woff2")' });
```

3. 全局 CSS：

```css
page {
  --font-display: 'Cormorant Garamond', 'Noto Serif SC', 'STSong', Georgia, serif;
  --font-body: 'Noto Serif SC', 'Cormorant Garamond', 'STSong', Georgia, serif;
  --font-nums: 'Cormorant Garamond', 'Noto Serif SC', Georgia, serif;
  --font: var(--font-body);
  font-family: var(--font);
  -webkit-font-smoothing: antialiased;
}
```

### 2.1 用户端首页 → 用户端首页下拉后页面

对应原型：

- 初始状态：`pages/client-home-glass-neu-contrast-1.html`（画布 `page-client-home-glass-neu-contrast-1`）
- 下拉后状态：`pages/client-home-glass-neu.html`（画布 `page-client-home-glass-neu`）

#### 首屏元素构成

**初始页首屏（从上至下）**

1. 状态栏（时间、信号、电池）
2. 问候语 `.greeting`："下午好"
3. 应用名 `.app-name`："自家人维修"
4. 玻璃搜索栏 `.search-bar`（在 Hero 内）
5. 三列统计卡 `.stat-card`
6. 横向热标签 `.hot-tags`
7. 服务网格 `.service-grid`
8. AI 助手卡 `.ai-card`、推荐师傅 `.section-title` + `.chips-row` + `.recommend-card`（首屏外，下拉后可见）。AI 卡仅进入 AI 助手，不替代订单聊天或人工客服

**下拉后页面首屏**

1. 状态栏
2. 固定标题栏 `.title-bar`（仅含搜索框）
3. 压缩后的 Hero（高度 115px，只保留状态栏 + 搜索栏）
4. 服务网格 `.service-grid`
5. AI 助手卡、推荐师傅、推荐服务

#### 顶部标题栏变化过程（重点）

HTML 原型通过 `.phone` 容器滚动 + `#titleBar` 类名切换实现，具体阈值如下：

| 滚动距离 `.phone.scrollTop` | 触发的类/状态 | 动画表现 |
|----------------------------|--------------|----------|
| `0 → 20px` | `.phone.scrolled` | 搜索框上方问候语 `.greeting` 渐隐并上移 12px |
| `0 → 40px` | `.title-bar.visible` | **顶部固定标题栏浮现**：从完全透明渐入，背景变为 `rgba(242,237,232,0.92)` + `blur(20px)`，显示应用名 `.title-bar__name`（"自家人维修"）。此时 Hero 内搜索框仍跟随页面上移，搜索框上方内容继续淡出 |
| `0 → 60px` | `.phone.scrolled-2` | 搜索框上方剩余内容清空：`.app-name`、Hero 内 `.search-bar`、`.hot-tags` 同时渐隐并上移；统计卡 `.stat-card` 也随滚动淡出 |
| `40 → 90px` | `.title-bar.search-mode` | **搜索框被推入固定标题栏**：标题栏从“显示应用名”切换为搜索态——应用名左移淡出，标题栏内搜索框 `.title-bar__search` 从 `scaleX(0.88)` 横向展开到 `scaleX(1)` 并淡入 |
| `≥ 90px` | 进入下拉后页面 | Hero 区域压缩为只剩状态栏 + 搜索栏（高度 115px）；下方 `.service-grid`、`.ai-card`、`.section-title`、`.chips-row`、`.recommend-card` 依次入场 |

关键约束：

- 顶部标题栏始终 `position: fixed`，不随 `.phone` 滚动而移动。
- Hero 内搜索框与标题栏内搜索框不会同时可见：Hero 搜索框在 `> 60px` 淡出，标题栏搜索框在 `> 90px` 淡入。
- 这是先把搜索框推到固定位置、搜索框上方内容渐隐；然后标题栏进入搜索态、应用名渐隐的过程。

#### 动画过程总表

| 滚动阶段 | 触发元素 | 动画表现 | 建议实现 |
|----------|----------|----------|----------|
| 0 → 20px | `.greeting` | `opacity 1→0`，`translateY(0→-12px)` | `scrolled` 类 |
| 0 → 40px | `.title-bar` | 透明度 0→1，背景模糊出现 | `.visible` 类 |
| 0 → 60px | `.app-name`、Hero `.search-bar`、`.hot-tags`、`.stat-card` | 整体上移并淡出 | `.scrolled-2` 类 |
| 40 → 90px | `.title-bar__name` → `.title-bar__search` | 应用名左移淡出，搜索框横向展开淡入 | `.search-mode` 类 |
| 90px → | `.service-grid`、`.ai-card`、`.section-title`、`.chips-row`、`.recommend-card` | 依次从下方滑入 | 按滚动偏移量或 IntersectionObserver |

### 2.2 实时追踪 → 实时追踪下拉页面

对应原型：

- 初始状态：`pages/client-order-tracking.html`（画布 `page-client-order-tracking`）
- 下拉后状态：`pages/client-order-tracking-2.html`（画布 `page-client-order-tracking-2`）

#### 首屏元素构成

**初始页**

1. 置顶导航栏 `.nav-bar`：返回按钮、标题"实时追踪"（17px）、刷新按钮；渐变背景，底部圆角 28px
2. 地图区域 `.tracking-map-section`：模拟地图、路线、师傅/目的地标记，高度 420px
3. 状态横幅 `.tracking-status-bar`：浮在地图底部（`margin:-32px 20px 0`），显示“师傅正在赶来 · 约10分钟到达 · 1.5km”
4. 师傅信息卡 `.tracking-worker-card`
5. 服务进度时间轴 `.tracking-timeline`

**下拉后页面**

1. 置顶组合头 `.top-header`：内含 `.hero`（标题 22px，底部圆角 32px）+ `.filter-tabs`（状态卡片，重叠在 Hero 下方）
2. 地图区域 `.tracking-map-section`（高度收缩或留白）
3. 师傅信息卡、服务进度时间轴
4. 底部“查看订单详情”链接 `.order-detail-link`

#### 顶部标题栏变化过程

| 滚动阶段 | 触发元素 | 动画表现 |
|----------|----------|----------|
| 0 → 60px | `.nav-bar` | 顶部栏由普通导航栏扩张为 Hero 形态：标题字号 17px → 22px，背景渐变加深，底部圆角 28px → 32px，高度随 padding 增加 |
| 0 → 80px | `.tracking-status-bar` | 状态横幅从地图底部随滚动上浮，最终嵌入 `.top-header` 的 `.filter-tabs` 位置；宽度由带边距扩展为接近通栏 |
| 0 → 120px | `.tracking-map-section` | 地图区域高度由 420px 收缩到约 120px；内部地图 `scale(1→0.92)`，路线/标记透明度降低 |
| 60 → 120px | `.top-header` | 原 `.nav-bar` 完全演变为 `.top-header`（Hero + Filter Tabs 组合），两侧按钮的视觉圆面由 44px 玻璃态变为 40px 透明态，但外层点击热区始终不小于 44px |
| 120px → | `.tracking-worker-card`、`.tt-item`、`.order-detail-link` | 内容依次从下方滑入/淡入；时间轴节点 stagger 100ms |

> 记忆点：状态横幅从地图底部“漂浮”到顶部组合头里，是实时追踪页下拉动画的核心。

    <view class="tracking-map" style="{{mapInnerStyle}}">...地图...</view>
  </view>

  <view class="tracking-worker-card">...</view>
  <view class="tracking-timeline-card">...</view>
  <view class="section section-link">
    <button class="order-detail-link">查看订单详情</button>
  </view>

```js
onTrackingScroll(e) {
  const y = e.detail.scrollTop;
  const mapHeight = Math.max(120, 420 - y);
  this.setData({
    morphed: y > 60,
    statusFixed: y > 80,
    mapStyle: `height:${mapHeight}px`,
    mapInnerStyle: `transform:scale(${Math.max(0.92, 1 - y*0.0002)});opacity:${Math.max(0.3, 1 - y/120)}`,
    statusStyle: y > 80 ? 'position:fixed;top:...;width:100%;z-index:100' : `transform:translateY(${-y}px)`
  });
}
```

定位与页面生命周期约束：

- 追踪会话绑定 `service_state=departing` 的订单，而不是绑定实时追踪页或位置上报页。打开系统导航、拨打电话、切到后台、页面 `hide/unload` 都不能直接结束会话。
- 师傅端默认每 15 秒上报一次，用户端每 10 秒或通过实时事件刷新；频率由服务端配置统一下发。
- 超过 60 秒没有新位置时，必须展示最后更新时间并停止输出不可靠 ETA；用户端提供联系师傅/客服，师傅端提供重试/去设置/客服。
- 用户端只查看位置和履约状态，不能以刷新、到达确认等交互推进订单；“到达”“开始服务”均由师傅端按 `allowed_actions` 展示与执行。

### 3.2 底部导航栏（师傅端 / 用户端固定）

```css
.tab-bar {
  position: fixed;
  bottom: calc(14px + env(safe-area-inset-bottom));
  left: 50%; transform: translateX(-50%);
  width: calc(100% - 32px); max-width: 360px; height: 56px;
  z-index: 100;
}
```

根页面信息架构固定如下，不得再增加第 5 个“设置”等入口；“财务”统一命名为“钱包”。详情页、表单页、支付页、聊天页和定位页隐藏 Tab Bar。

| 角色 | Tab 1 | Tab 2 | Tab 3 | Tab 4 |
|------|-------|-------|-------|-------|
| 用户端 | 首页 | 发布 | 订单 | 我的 |
| 师傅端 | 接单 | 订单 | 钱包 | 我的 |

两端“我的”均保留固定角色切换入口：用户端显示“切换到师傅工作台”，师傅端显示“切换到找服务”；尚未开通师傅身份时显示“申请成为师傅”。切换角色只切换工作台，不退出登录。

根页面固定展示对应的 4 个 Tab，非根页面不展示。

小程序要点：

- 使用 `cover-view` / `cover-image` 保证在地图、scroll-view 等原生组件上层可点击。
- 底部预留 `padding-bottom: calc(56px + env(safe-area-inset-bottom) + 14px)`。

### 3.7 业务状态、任务优先级与异步反馈

业务状态色跨用户端与师傅端固定，不跟随品牌色切换：

```css
page {
  --status-bidding: #D4944C;
  --status-accepted: #5A8FAD;
  --status-departing: #0D9488;
  --status-arrived: #5B8C5A;
  --status-serving: #D4944C;
  --status-payment: #C4533A;
  --status-review: #5A8FAD;
  --status-completed: #5B8C5A;
  --status-cancelled: #7C746D;
  --status-error: #C4533A;
}
```

- 根页面内容优先级固定为：当前任务 / 待处理事项 → 高频入口 → 推荐与营销。存在当前订单、待确认差价、待支付、待评价或履约异常时，顶部必须先呈现当前任务卡，不能被推荐内容挤到首屏之外。
- 页面必须覆盖 `Initial / Loading / Success / Empty / Partial / Error / Offline / Restricted` 八类状态；状态切换不能仅靠 Toast 表达。
- 发布、报价、支付、退款、上传等异步动作使用任务卡持续反馈 `draft / submitted / processing / action_required / succeeded / failed / cancelled`（草稿 / 已提交或排队中 / 处理中 / 需处理 / 成功 / 失败 / 已取消），允许用户离开当前页后从当前任务或消息入口继续查看和处理；不得用一次性“提交成功”冒充最终结果。

### 3.8 减少动态效果

系统启用“减少动态效果”时，关闭位移、缩放、弹簧、交错入场、脉冲和骨架闪烁；滚动变形直接落到可读的稳定标题栏状态。可保留不超过 120ms 的透明度/颜色过渡，按压态即时反馈，不能通过移除焦点、加载、成功或错误反馈来“减动效”。

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation: none !important;
    scroll-behavior: auto !important;
    transition-property: opacity, color, background-color, border-color !important;
    transition-duration: 120ms !important;
  }
}
```

## 四、微信运行时适配基线

### 4.1 系统几何与固定层级

- 启动时通过微信当前支持的窗口与胶囊按钮 API 获取状态栏、安全区和菜单位置，计算导航栏高度；读取失败时使用经过真机验证的保守兜底，不能把某台手机的 `44px` 状态栏写成全局常量。
- 同一页面只有一个纵向滚动容器。滚动监听用 `requestAnimationFrame` 或等价节流，只在阈值跨越时更新布尔状态；连续视觉变化优先使用 `transform / opacity`，避免高频 `setData` 传大对象。
- 固定层级统一为：页面内容 `<` sticky 标题栏 `<` Tab Bar / 固定 CTA `<` Sheet / 遮罩 `<` Toast。地图、视频、相机等原生组件上方需使用微信支持的覆盖层方案并真机验证。
- 页面主体始终预留“固定操作栏 + 底部安全区 + 16px”；键盘弹起时输入区随可视区域上移，聊天页保持最后一条消息可见。

### 4.2 角色主题与自定义 Tab Bar

- 页面根节点只挂一个角色主题类，由它切换品牌 Token；订单、支付、售后和异常仍使用固定 `--status-*`，不得随主题变色。
- 角色切换成功后一次性提交 `activeRole`、主题类、四项 Tab、权限、未读数和目标根页面，再建立新导航栈；任一数据缺失或切换失败时保持原角色界面，不先换色、不展示目标角色按钮。
- 自定义 Tab Bar 只在八个双端根页面显示；详情、表单、支付、聊天、地图和考试页隐藏。Tab 重选回到该根页稳定态，角色切换后返回键不能回到旧角色根页。

### 4.3 网络、图片与上传

- 监听网络状态并映射到页面的 `Offline / Partial / Error`；真实接口失败不得自动回退 Mock。恢复网络后先刷新对象版本，再决定是否重试原动作。
- 列表图片懒加载，头像、服务图和凭证图分别提供语义占位；加载失败只替换该资源，不清空整页数据。
- 多图上传逐项记录 `waiting / uploading / succeeded / failed`，失败图片可单独重试；页面离开前保存草稿，重复提交沿用同一幂等键。

### 4.4 权限、键盘与系统中断

- 权限在用户触发相关动作时申请：选择当前位置可拒绝后手动选地址；师傅点击“出发”前预检定位，拒绝时阻止状态迁移并提供“去设置 / 联系客服”。不能先改变订单状态再申请权限。
- 打开地图导航、系统拨号、相册、相机或支付后，返回小程序先查询原订单、上传或支付结果；不能把 `onShow` 当作操作成功。
- 输入页监听键盘高度，固定按钮或输入栏不遮挡焦点字段；收起键盘后恢复原安全区。表单值、选择项和滚动位置在前后台切换后保留。
- 页面 `hide / unload`、电话和导航不结束订单定位会话；只有到达、取消、平台终止等服务端认可原因才能停止。

### 4.5 性能与兼容

- 同屏大面积高模糊玻璃不超过主样式规范的预算；低性能设备按“降低模糊 → 移除辉光 → 实色表面”降级，不减少业务信息。
- 字体、图片和动效失败都不能阻塞主任务；系统字体放大、减少动态效果、320px 小屏和不同安全区必须进入回归矩阵。
- 本规范不预设尚未立项的深色主题，也不固定分包目录；新增主题或分包前先形成独立技术决策和回归证据。
