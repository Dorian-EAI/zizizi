# zjrnew.design → 微信小程序同步流程

> 适用版本：产品 v6.2  
> 本流程只保证**视觉画布同步**，不代表功能、路由或业务状态已经可用。

## 文档权威层级

1. `../PRD_v6.0.md`：**业务规则的唯一事实源**（文件名为兼容路径，正文版本为 v6.2），包括业务范围、角色权限、状态迁移、资金结果和异常规则。
2. `../docs/design/功能与交互文档.md`：入口、操作、返回、权限反馈和异常恢复的体验事实源；不得覆盖 PRD 的业务规则。
3. `../docs/design/样式规范详尽文档.md`：视觉 Token、组件、布局规则、动效边界和视觉验收的事实源。
4. `../zjrnew/zjrnew.design`：评审后已登记页面的具体几何与画面来源，包括画布尺寸、元素位置与顺序、精确间距、圆角、阴影、透明度、渐变和滚动状态。
5. [`../docs/design/小程序动画与布局实现规范.md`](../docs/design/小程序动画与布局实现规范.md)、HTML/CSS 及小程序代码：特殊动效、布局与运行实现。差异必须登记，不能反向改写以上规范。

只有 `.design.data[]` 中声明的节点属于正式**画布节点**；目录中未被 `.design` 引用的 HTML 不得自动加入小程序。`.design` 引用的 HTML 是画布登记渲染源，不拥有高于 `.design` 的视觉权威。功能是否正式、入口如何到达、操作是否允许，以 PRD 业务规则为准。

不得为了迁就接口字段、现有组件或开发便利而擅改画布。若画布与 PRD、交互或样式规范冲突，必须暂停同步并完成评审：先修正规范或由设计源所有者更新 `.design`，再迁移和接受基线，不能让实现者自行选择其中一份覆盖另一份。

## 更新步骤

1. 在设计工具中修改画布，并确保 `.design` 的 `layoutSnapshot.sourceHash`、`viewportWidth`、`contentHeight` 和 `devMetadata.htmlSrc` 已更新。
2. 在小程序目录执行 `node tools/design-sync.mjs`。
3. 查看 `DESIGN_SYNC_REPORT.md` 的“检测到的源变更（未验收 / 未接受基线）”，确认变更归属；检测到变更不等于已经同步，不得直接接受基线。
4. 按照 Design ID 逐页更新报告对应的 `pages/<target>`，不得在迁移过程中反向修改 `.design`。
5. 迁移必须保持：375px≈750rpx、画布内容高度、节点顺序、精确间距、圆角、阴影层、透明度、渐变停靠点、字体层级和滚动态。
6. 按 `devMetadata.interactions` 迁移视觉点击目标，并依据 PRD 复核操作权限与结果；必要的稳定入口、帮助和异常恢复不得因画布遗漏而被删除。HTML DOM 状态改写为微信小程序数据状态。
7. 在微信开发者工具按报告中的画布宽高截图，与画布截图叠加比对。建议使用 50% 透明度差分，修正到主要边缘重合。
8. 只有在所有变更均已逐页验收、且设计源所有者确认新画布后，才运行 `node tools/design-sync.mjs --accept`。检测阶段禁止为消除报告中的变更数而执行 `--accept`。
9. 发布前执行 `node tools/release-gate.mjs`，同时验证运行断链和设计同步状态；该命令不会自动接受设计基线。

## 强校验

同步工具会阻止以下情况被确认为新基线：

- `.design` 引用的 HTML 缺失；
- HTML 的 FNV-1a 与画布 `sourceHash` 不一致；
- Design ID 的交互指向不存在的目标节点；
- 小程序页面四件套缺失；
- 核心颜色与材质辅助令牌偏离当前画布渲染资产。

强校验只覆盖节点、文件、哈希、交互目标和部分视觉令牌，不覆盖像素差分，也不覆盖登录恢复、角色切换、订单状态、权限、支付、位置追踪、资金结算或售后闭环。像素视觉以 `.design` 逐页验收，业务行为按 PRD 走查。

首页和实时追踪各有两个滚动状态节点，分别共同映射到同一个小程序页面，由滚动状态切换实现。`entry` 与 `search` 是小程序运行辅助页，不计入 `.design` 视觉节点覆盖率。

## 同步后业务核对

- 用户端 Tab：`首页 / 发布 / 订单 / 我的`；师傅端 Tab：`接单 / 订单 / 钱包 / 我的`。
- 首页当前任务优先于推荐内容；详情、支付、聊天、地图和考试页隐藏 Tab Bar。
- 用户选中报价后直接进入已接单；“到达/开始服务/完工”由师傅端按状态推进。
- AI 助手、订单聊天和人工客服使用不同标题、入口与目标页。
- 支付渠道、允许操作和师傅资格由服务端返回，页面不得根据画布示例硬编码。
- 每个正式入口均有加载、空、错误、受限和返回兜底状态。
