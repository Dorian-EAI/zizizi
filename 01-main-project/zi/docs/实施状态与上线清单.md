## 2. 当前实现状态

### 已接通并具备自动检查

- 小程序注册页数始终以 `app.json` 实际内容为准。最新一次重读时为 44 页：42 个既有视觉目标、入口和搜索两个辅助页面；其中已包含登录授权、在线客服、积分中心、邀请奖励、确认支付、服务评价和差价确认 7 个此前新增页面。
- `zjrnew.design` 已再次扩展为 129 个节点、127 个唯一目标页面。画布同步工具当前报告 44/129 个节点已有完整目标四件套，85 个仍缺失；快照哈希异常为 0、基线后变更 131。批量迁移、注册、截图比对和人工验收尚未完成，这是当前发布阻断，不能直接执行 `--accept` 消除。
- 用户/师傅微信登录、手机号验证码绑定、订单主链路、报价、定位、评价、客服工单和证据上传已接真实 API 契约。
- 微信 JSAPI 支付与退款具备签名/解密、商户号、金额、幂等和回调校验；真实回调成功前不入账。
- 用户钱包/JSAPI 充值、钱包/JSAPI 订单支付和退款发起使用持久化 `Idempotency-Key`：体验/生产缺键返回 428，同账号同键同请求重放原结果，同键改操作或参数返回 409；服务中断留下 `processing` 时失败关闭并要求按业务单号核对。
- 管理员接口使用短期 JWT 和账号会话版本；API 创建/重置的管理员必须首次改密，改密、禁用和登出会使旧 Token 失效；高风险退款、提现审批、保证金扣款、账号管理和受管文件删除要求超级管理员并写持久化审计。
- 短信、AI、上传、支付和微信登录在生产环境失败关闭，不会把 mock 或本地降级伪装成真实成功。
- 生产启动不执行 `create_all`、不自动 seed 或创建默认管理员；数据库必须已由 `alembic upgrade head` 管理。代码和门禁通过 Alembic `ScriptDirectory` 动态取得预期 head 并与数据库当前 revision 精确比较，不在文档中硬编码一个可能过期的 head。
- 阿里云 OSS / 腾讯云 COS 上传和删除校验当前 bucket 主机与服务端受管 key；证件对象强制私有 ACL、后台十分钟短签名读取，只有超级管理员可删除并记录 attempted/deleted/not_found/failed 审计结果。
- `run.py` 支持 `WEB_CONCURRENCY=1..32`（热重载必须为 1）；当前 12 类调度任务使用 Redis 所有者令牌锁跨进程/副本去重，部署环境 Redis 不可用时跳过任务而非无锁执行。
- `/health` 用作存活探针，`/ready` 验证数据库、迁移和生产 Redis。

### 已安全关闭，不能按“已上线功能”宣传

以下能力缺少真实资金通道、库存/补贴账本或外部回调闭环。当前接口明确返回不可用，且不会先扣款、发权益或修改最终状态：

- 家庭年卡购买、使用和退款；
- 积分兑换优惠券；
- 保险投保与审核通过后的真实赔付；
- 师傅保证金真实支付与原路退款；
- 生产环境主动提现/商家转账到账确认；
- 钱包加微信的组合支付（在超时释放与对账闭环完整验收前保持关闭）；
- 师傅收入钱包充值和师傅间转账；`page-worker-recharge` 已按画布注册为禁用的视觉对照页，但无正式入口、提交只提示不可用，后端两条充值入口对师傅令牌返回 403；保证金仍走独立流程；
- 客服工单直接退款或直接扣保证金。

重新开放任一能力前，必须补齐真实渠道、账务分录、幂等键、失败重试、对账、审计和专项测试，不能只删除 `501/503`。

### 仍未完成的 v6.3 产品收口

- 订单已输出履约、支付、售后、补差价、验收五轴与统一 `allowed_actions`；一口价/自己定价“下单即托管”的支付时点、空跑费自动记账和验收放款仍需与真实资金通道联调。
- v6.3 接口（`/api/catalog/*`、师傅原子接单、验收、空跑费、加速接单、结算查询）已落地，并通过 pytest 内存 SQLite 回归；MySQL 迁移演练与真机/用户验收仍未完成。
- 已接单后的取消申请、争议、退款/理赔编排和全部消息深链仍需端到端补齐。
- 同账号双角色的角色范围 Token、动态四 Tab、页面栈恢复和所有异常续办仍需完整验收。
- 真实微信支付/退款、订阅消息、短信、对象存储、地图和 AI 必须使用部署方凭据完成沙箱与生产演练。

## 3. 画布更新流程

在 `wxapp` 目录执行：

```powershell
node tools/design-sync.mjs
```

推荐顺序：

1. 先按主 PRD、交互和样式规范确认业务状态与视觉规则，再在 `zjrnew.design` 更新画布并同步画布登记的渲染源。
2. 运行同步工具。存在新源变更时返回非零并生成 `DESIGN_SYNC_REPORT.md`，其中会列出受影响源和目标页面。
3. 只修改报告指向的小程序 WXML/WXSS/必要交互文件，保持 `.design` 的几何、材质、布局和状态画面。
4. 在微信开发者工具分别检查 375×900 与画布指定 374/375×900 视口，并覆盖滚动状态、系统字体放大、减少动画和安全区。
5. 运行 JavaScript、JSON、接口和后端测试；人工逐页通过后，再执行：

```powershell
node tools/design-sync.mjs --accept
```

`--accept` 只确认当前画布基线，不能代替肉眼截图比对和业务验收。详细步骤见小程序目录的 `样式画布同步流程.md`。

## 4. 发布前配置

### 小程序

- 在 `config/env.js` 为 `trial`、`release` 填写真实 HTTPS API 根地址。
- 在微信公众平台配置 request、uploadFile、downloadFile、socket 及业务域名白名单。
- 体验版和正式版必须保持 `allowMock=false`、`useMock=false`。
- 校验合法 AppID、隐私保护指引、用户信息/手机号/位置权限和订阅消息模板。

### 后端

- 体验环境 `APP_ENV=staging`、正式环境 `APP_ENV=production`；两者都要求 `APP_DEBUG=false`、MySQL、Redis 和 Alembic 当前动态 `head`，不允许开发降级，也不允许启动时 `create_all` 或 seed。
- 随机 JWT 密钥、固定 PII 加密密钥、CORS 与 Host 白名单；生产必须 `ENABLE_BUILTIN_ADMIN=false`，另行部署安全管理前端。
- 迁移完成且 `admins` 表为空时，使用 `python scripts/bootstrap_super_admin.py --username <账号>` 一次性创建首个超级管理员，密码隐藏输入或由 Secret Manager 经 `--password-stdin` 传入。脚本录入最终密码；后续 API 创建/重置账号必须完成首次改密后才能使用后台。
- 微信 AppID/Secret、支付商户号、API v3 密钥、商户私钥、证书序列号及 HTTPS 支付/退款回调。
- 当前生产配置门禁把短信、对象存储、地图和 AI 均列为真实必配能力；仅隐藏前端入口不能绕过配置校验。地图在 `staging/production` 禁止 local 直线距离降级，必须使用高德或腾讯真实路线服务。
- 对象存储必须 `CERTIFICATE_PRIVATE_STORAGE=true`；在测试 bucket 演练私有上传、短签名、受管 key 删除与删除审计，并完成对象版本、未完成分片、保留/清理规则后，才可将 `OBJECT_STORAGE_LIFECYCLE_CONFIRMED=true`。仍被认证记录引用的证件不能依赖 bucket 自动过期。
- 反向代理只有在源站禁止公网绕过时才开启 `TRUST_PROXY_HEADERS`。
- `WEB_CONCURRENCY` 按容量设置为 1–32；多 worker/多副本任务必须共用 Redis，让所有者令牌锁避免重复执行，也可仅在独立 scheduler 实例设置 `SCHEDULER_ENABLED=true`。

## 5. 自动发布门禁

先在全新的 Python 3.12 虚拟环境安装锁定依赖并验证依赖图，不能以开发机已缓存的包代替发布证据：

```powershell
Set-Location server
py -3.12 -m venv .venv-release
& .\.venv-release\Scripts\python.exe -m pip install --upgrade pip
& .\.venv-release\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv-release\Scripts\python.exe -m pip check
```

再在 `server` 目录执行：

```powershell
python scripts/check_production_readiness.py --env-file .env --run-tests
```

部署环境可增加只读连通性检查：

```powershell
python scripts/check_production_readiness.py --env-file .env --run-tests --online
```

门禁会检查生产安全配置、所选 Provider SDK 和密钥/证书格式、小程序 AppID 与后端 `WX_APPID` 一致、体验版/正式版域名和客服电话、合法域名校验与 Mock 隔离、全部 JS/JSON、`zjrnew.design` 同步、后端测试、OpenAPI 唯一性；`--online` 还会检查生产数据库、动态 Alembic head、运营内容、启用服务类目、已完成密码生命周期的超级管理员、主 Redis 与限流 Redis。脚本不会迁移数据库、发送短信或发起资金请求。

本仓库当前仍有以下发布阻断，因此门禁应返回非零，不能把代码回归通过解释为已经上线：

- 最新设计报告仅完成 44/129 个节点映射，85 个目标仍缺失且有 131 个基线后变更，尚未批量实现、注册、截图比对并人工接受；
- 小程序 `trial/release` 的 API 地址和客服电话为空，后端 `WX_APPID` 尚不能与小程序 AppID 完成生产交叉校验；
- 生产 MySQL/Redis、JWT/PII 密钥、微信登录/支付、平台证书、短信、对象存储、地图和 AI 的真实配置尚未由部署方注入；
- 生产库尚需执行真实 MySQL 8 迁移/回填/对账，并发布协议、隐私、帮助、FAQ、启用服务类目和首个超级管理员；
- 私有对象存储与生命周期、多 worker 调度锁、支付/退款回调、订阅消息、短信、地图、备份恢复和独立生产管理前端尚需在真实基础设施演练。

## 6. 标准发布顺序

1. 备份数据库并在隔离环境验证恢复。
2. 在一次性 MySQL 8 环境先演练 `alembic upgrade head`、`alembic current`、`alembic check` 和资金对账；生产执行同一迁移后再运行发布门禁 `--online`。
3. 在干净 Python 3.12 环境完成 `pip check` 与全量测试，部署后端但暂不切流，确认 `/health` 与 `/ready`。
4. 使用微信支付沙箱/最小额订单验证下单、回调、查单、退款回调和重复通知。
5. 验证短信、订阅消息、对象存储、地图路线、定位权限和 AI 超时失败提示。
6. 上传体验版，完成用户端“我的 > 切换到师傅工作台”和师傅端“我的 > 切换到找服务”的双向回归；切换不退出登录、不终止任务/位置/资金，再完成全链路回归后提交审核。
   - 没有师傅档案的账号必须显示“我的 > 申请成为师傅”，完成或退出开通流程后返回来源页；不得显示一个注定失败的切换按钮。
7. 以至少两个 web worker 或两个副本验证同一调度任务只有一个 Redis 锁持有者执行，并在测试 bucket 演练私有证件读取和受管对象删除审计。
8. 灰度发布并监控支付回调失败、幂等冲突/处理中请求、账实差异、5xx、Redis/数据库就绪和调度锁。

若发布门禁失败、迁移不可逆、账实不一致或回调验签失败，停止切流并按数据库备份、应用上一版本和微信后台回调配置三部分分别回滚。
