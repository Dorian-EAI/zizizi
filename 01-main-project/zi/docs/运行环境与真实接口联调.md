# 运行环境与真实接口联调

> 适用产品规则：v6.3  
> 业务契约：`../PRD_v6.0.md`；后端目标契约：`../PRD_BACKEND_v2.0.md`  
> 本文区分“当前可联调实现”和“v6.3 必须达到的验收契约”，Mock 通过不等于真实链路通过。

运行配置位于 `config/env.js`。小程序根据微信的 `envVersion` 自动选择：

- `develop`：默认连接 `http://localhost:8000`，允许开发者显式启用 Mock。
- `trial`：体验版，仅允许 HTTPS 真实接口，禁止 Mock。
- `release`：正式版，仅允许 HTTPS 真实接口，禁止 Mock。

发布体验版或正式版前，必须在 `config/env.js` 填写对应环境的 `baseURL`，并把该 HTTPS 域名加入微信公众平台的 request/uploadFile 合法域名。地址不含 `/api` 后缀。

## 本地开发切换

开发者工具控制台可执行：

```js
// 显式启用 Mock，重新编译后生效
wx.setStorageSync('__DEV_USE_MOCK__', true)

// 恢复真实接口
wx.setStorageSync('__DEV_USE_MOCK__', false)

// 覆盖本地 API 地址，重新编译后生效
wx.setStorageSync('__DEV_API_BASE_URL__', 'http://127.0.0.1:8000')
```

上述本地存储开关只在 `develop` 生效；体验版和正式版不会读取它们。真实接口发生 401、超时或连接失败时会如实提示，不会自动使用模拟数据。

## 联调前检查

1. 启动后端并确认微信登录所需 AppID/AppSecret 已配置。
2. 从入口页点击用户端或师傅端，验证 `wx.login`、Token 保存及 `/api/auth/me` 对应角色资料。
3. 将 Token 改为无效值，确认请求 401 后回到入口页且不会展示 Mock 数据。
4. 用已完工订单验证 JSAPI 支付参数和 `wx.requestPayment`。
5. 用已投保订单验证保单查询、证据图片上传与理赔提交。
6. 在客服中心验证工单列表、筛选、详情和新建工单。

## v6.3 契约核对

真实接口至少要能表达以下信息，页面不得靠本地枚举猜测：

| 领域 | 必要字段/能力 |
|------|---------------|
| 登录与角色 | 当前账号可用角色、师傅准入状态、角色受限原因；登录后恢复 `return_to/pending_action/draft_id` |
| 订单 | `service_state`、`payment_state`、`aftersale_state`、`price_adjust_state`、`allowed_actions`、事件版本 |
| 报价 | 草稿/已提交/已选中/未选中/过期/撤回，报价截止时间、费率快照、预计到手 |
| 师傅资格 | 当前订单是否可报价及逐项阻塞原因，不只返回单个“已认证”布尔值 |
| 位置 | 与订单绑定的追踪会话、最后更新时间、上报间隔、位置过期和恢复状态 |
| 支付 | 服务端可用渠道、幂等支付单、结果查询；未知结果不得重复下单 |
| 钱包 | 待结算/可提现/冻结/提现中/已到账/冲正资金桶及预计时间 |
| 消息 | 角色、对象类型、对象 ID、事件版本、兜底路由和按角色未读数 |
| 异步任务 | 认证、提现、退款、理赔、工单等的状态、责任方、预计时间和下一步 |

若当前后端尚未返回某字段，联调记录必须标记为“目标契约未实现”，不能使用固定 Mock 值伪装完成。

## 关键链路验收

### 身份与导航

1. 同一账号先在用户端“我的”点击“切换到师傅工作台”，再在师傅端“我的”点击“切换到找服务”；不退出登录，不串用订单、钱包与未读。
2. 未申请、草稿、审核中、已启用、资质过期/受限分别验证进入范围和修复入口。
3. 用户端四 Tab 与师傅端四 Tab 的根页面、重选、返回和深链兜底一致。
4. 师傅钱包展示六资金桶和提现/保证金入口，不出现收入钱包充值或师傅间转账。

### 交易主链

1. 三步发布 → 多师傅报价 → 用户选择 → 师傅待出发。
2. 师傅出发 → 位置追踪 → 到达 → 开始服务 → 必要时差价确认 → 完工。
3. 客户支付 → 师傅待结算 → 可提现 → 提现结果。
4. 客户评价，以及取消、退款、投诉、理赔、申诉等独立售后状态。

重点断言：用户选中报价后不再要求师傅二次接单；用户不能推进“开始服务”；差价同意不立即扣款；师傅完工不能绕过已确认价格自由改价。

### 异常与恢复

- 401 登录后回原任务，表单草稿和已选地址/优惠券仍在。
- 报价过期、状态被另一端更新、支付结果未知、提现超时先查原结果。
- 定位拒绝阻止出发但保留订单；导航/电话/前后台切换后恢复位置会话。
- 位置超过 60 秒未更新时，双端显示最后时间和恢复/联系入口。
- 图片上传部分失败可单张重试；网络恢复不覆盖用户正在编辑的内容。
- 消息目标失效时进入最新对象或明确失效页，不吞未读。

## 发布门禁

- 提交或联调前执行 `node tools/runtime-integrity.mjs`。它以 `app.json` 的 37 条正式路由为边界，检查页面四件套、导航目标、`usingComponents`、本地模块、WXML/WXS/WXSS import、本地资源与运行脚本语法。
- 上传体验版或正式版前执行 `node tools/release-gate.mjs`。该门禁依次执行运行完整性和 `zjrnew.design` 同步检查，任一非零退出码都禁止上传。
- `design-sync` 因“未验收 / 未接受基线”的设计源变化返回 1 是预期阻断；必须先完成逐页视觉验收，不能为了通过门禁直接运行 `--accept`。
- `.backups` 只用于人工留档，已通过 `project.config.json > packOptions.ignore` 排除，不得被页面、组件、模板、样式或脚本引用。
- 静态门禁不依赖微信开发者工具 CLI；门禁通过后仍须在可用的微信开发者工具中完成真机、权限、网络、支付和截图人工验收。
- 体验版和正式版不得读取 Mock，也不得把“功能开发中”作为正式入口结果。
- 每项正式功能必须在页面注册表中具备稳定入口、上下文入口、前置条件、成功落点和错误恢复。
- 真实接口、数据库迁移、支付回调和关键定时任务通过后端回归测试后方可发布。
